## Premise

The v0.1.0 bashrs IR merger shipped under the discipline of the
**XPILE-UNMERGE-001 falsifier**. From `sub/bashrs-merger.md`:

> v0.3.0 check-back: if no cross-domain producer of shell variants
> ships before the v0.3.0 release, the merger is reverted.

Three eligible options were listed:

- **(a)** Python `subprocess.run([...])` recognition ✅ **shipped at v0.1.0** (PMAT-040..058, evidence at `crates/xpile/tests/fixtures/subprocess_demo.py` + `crates/xpile/examples/05_python_to_shell.rs`)
- **(b)** Rust `Command::new(...).arg(...)` recognition — *not shipped*
- **(c)** Lean theorem about shell composition — *not shipped*

The XPILE-UNMERGE-001 falsifier is **already discharged** by (a).
This sub-spec is about **margin of safety**, not bare survival.

## Why pick up a second discharge?

Single-point-of-failure: (a) is one fixture (`subprocess_demo.py`)
and one example (`05_python_to_shell.rs`). If a future refactor
breaks the subprocess.run lowering, the falsifier fires.

Two discharges = the falsifier survives the loss of either one.
Specifically, the Diamond program's UNIVERSAL ratchet teaches that
**redundant proofs are cheap and resilient**; the same logic
applies here.

## The pick: option (c)

**Recommendation: pick option (c) — Lean theorem about shell
composition.** Reasons:

1. **Compounds with the Diamond program.** A Lean theorem about
   shell-composition idempotence is naturally a Diamond-tier
   theorem for `C-BASHRS-POSIX-IDEMPOTENCE`. So this discharge
   advances Diamond depth simultaneously.
2. **Cheap.** Composition idempotence (`cmd ; cmd ≡ cmd` for the
   idempotent subset; `mkdir -p`, `chmod`, etc.) is a known
   theorem. ~3 days of Lean work, not a multi-week implementation.
3. **No new infrastructure.** Option (b) requires waking the
   xpile-folded Rust frontend, which is currently a scaffold.
   Option (c) only needs Lean theorems, which are already a v0.1.0-
   shipped substrate.

Option (b) stays open as a v0.3.0 candidate.

## Sequencing

### 3.A The composition-idempotence theorem (~3 days)

1. Identify the **idempotent subset** of shell commands. Initial
   pick: commands whose effect set is closed under repetition.
   - `mkdir -p <path>` (creates only if not present)
   - `chmod <mode> <file>` (sets exact mode)
   - `touch <file>` (creates or no-ops)
   - Redirects to overwrite (`> file`) — last write wins, idempotent
     for identical writers
   - Variable assignments (set last value)
2. Write `contracts/lean/Bashrs.lean` Diamond theorem:
   ```lean
   /-- For commands in the idempotent subset, sequential
       composition `cmd ; cmd` is observationally equivalent
       to `cmd`. -/
   theorem composition_idempotence_diamond
     (cmd : ShellCmd)
     (h : cmd.is_idempotent) :
     observe (compose cmd cmd) = observe cmd := by
     cases cmd
     · -- mkdir_p case
       sorry  -- discharged via constructor
     -- other constructors
   ```
3. Wire as Diamond theorem in `contracts/bashrs-posix-idempotence-v1.yaml`:
   ```yaml
   stratum_votes:
     - stratum: Semantic
       lean_theorem: composition_idempotence_diamond
       tier: diamond
   ```
4. Run `xpile diamond` → confirm depth-14 broadening on
   `C-BASHRS-POSIX-IDEMPOTENCE` (or higher, depending on what other
   diamonds wire up).

### 3.B Wire as discharge of XPILE-UNMERGE-001 (~half a day)

1. Update `sub/bashrs-merger.md` v0.3.0 check-back section: mark
   options (a) and (c) as discharged; option (b) remains open as
   v0.3.0+ candidate.
2. Add a falsifier-discharge note in
   `docs/specifications/audit-design.md`: "XPILE-UNMERGE-001 has
   two independent discharges (a + c). Loss of either does not
   trigger the unmerge."
3. CHANGELOG entry under v0.2.0.

## Risk register

| Risk | Mitigation |
|---|---|
| The full set of idempotent shell commands is debatable | Start small: 4-5 well-known idempotent forms. The contract claims "for cmds *in the marked-idempotent subset*", not "for all shell". |
| Lean proof might require non-trivial induction on `compose` recursion | Bound the theorem to single-statement composition first (`cmd ; cmd ≡ cmd`). Multi-statement and arbitrary-length sequences can be v0.3+ Diamond depth. |
| Theorem might fail to typecheck against existing `ShellCmd` AST | The `contracts/lean/Bashrs.lean` file is the source of truth for ShellCmd; if needed, extend its AST encoding to support the theorem (one-time cost). |

## What this is NOT

- **Not** "prove all of POSIX." The theorem is bounded to a
  decidable subset, mirroring `C-BASHRS-POSIX-IDEMPOTENCE`'s
  existing scope.
- **Not** a Rust frontend. That's option (b), still open for v0.3.0.
- **Not** *required* — the v0.3.0 check-back already passes on
  option (a) alone. This is defense-in-depth, in keeping with the
  Diamond program's "redundant proofs are cheap" philosophy.
